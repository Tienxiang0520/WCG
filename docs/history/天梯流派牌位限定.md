## 牌位限定方式

`tools/RankedDecks/build_ranked_decks.py` 的每個流派改用 `tiers=(…)` 明列可出現的牌位（`TIER_GATES`），不再自動繼承低牌位的所有流派。同一流派在不同牌位依該牌位的降級組數產生不同版本。

產生器會檢查每個牌位至少 8 種流派、涵蓋五種意志；`RankedDecks` 載入時也會驗證五種意志都在。

### 決定依據

先用 `build_ranked_decks.py --all-tiers --out <檔案>` 把 20 種流派放進每個牌位（120 副），以 RankedCheck 各模擬 400 場，量出每個流派在每個牌位的勝率，再依下列原則挑選：

- 嘲諷回血最強的白銀長城、誓約審判、荊棘毒牙只在大師；冰封堡壘在鑽石與大師。
- 即使在大師也偏弱的奧術控制、噬魂獻祭（約 66～68%）只留在青銅～黃金；占卜連鎖到白金為止。
- 戰鼓狂潮、灰燼殉爆、森林鋪場、野性衝鋒（大師約 76～85%）從大師退場；大師保留燃血突擊、深淵伏擊兩種快攻（81～82%），讓高段仍有不同節奏的對手。
- 各牌位平均勝率每階上升約 8～19 個百分點。

## 強度矩陣（玩家方使用不同強度電腦）

2026-10-09 補充：依作者回饋「模擬應該要用不同強度的 AI 測試，數據才有意義」。只用試玩電腦當玩家方，代表的是偏弱的玩家，所以改量完整矩陣。本節只是量測，未修改牌位限定、牌表或電腦強度。

### 方法

- `dotnet run --project tools/RankedCheck -c Release -- WcgWeb 200 --matrix`。
- 對手：各牌位電腦＋該牌位牌組池。
- 玩家方：五副試玩預組（新玩家的起始牌組），分別用試玩電腦與青銅～大師分級電腦操作。

- 同一種子結果固定，平行執行與單執行緒結果相同。
- 數字為**對手（天梯電腦）勝率**。

### 兩條主要曲線

- **對角線（玩家實力＝牌位，公平對局）**：46%、51%、47%、51%、52%、62%。
  - 青銅～鑽石都在五成上下，代表「實力與牌位相當」時勝負接近，爬升靠玩家進步。
  - 大師高出約 10 個百分點：大師牌組池全是完整牌表的強勢流派，比試玩預組強。
- **大師級玩家（近似強玩家）**：7%、16%、25%、31%、48%、62%。
  - 曲線穩定上升。最大的一階是白金→鑽石（+17），其次大師（+14）。
  - 強玩家在大師約 38% 勝率。天梯勝 1 星、敗扣 1 星，勝率低於五成會停滯，所以大師對只用預組的強玩家而言偏難，比較像終點門檻。

### 解讀與建議（尚未實作）

1. 曲線整體平順，沒有斷崖；公平對局維持五成，難度主要來自電腦分級。
2. **暗影刺殺**從黃金起就是各牌位最強（同牌位 73～79%），黃金、白金對大師級玩家也近五成，比同池其他流派高約 20 個百分點。建議改為只在鑽石與大師出現，或至少移出黃金。
3. **大師**的誓約審判、白銀長城對強玩家約八成。若希望大師「難但可打」，可：
   - 保留它們作為大師魔王，但降低抽中機率；或
   - 移出 1～2 個，換回戰鼓狂潮、灰燼殉爆等較平衡的流派，讓大師對角線接近 55%。
4. 白金→鑽石是最大一階。可把巨獸奔襲或聖盾防線的鑽石版本換成較弱流派，或讓冰封堡壘只在大師，以縮小落差。
5. 奧術控制、占卜連鎖、噬魂獻祭即使對同牌位玩家也只有 25～30%，在青銅～白金當「好打」的對手合理，不必調整。

### 決定性修正

建立矩陣時發現：黃金以上電腦在多選一抉擇分數相同時，以選項 Id 排序作為最後依據。卡牌選項的 Id 是每場隨機產生的 GUID，所以同一種子可能做出不同選擇；天梯回放（新的 GUID）也可能與原對局分歧。

已改為：GUID 選項同分時依選項順序決定，具名選項（KEEP、HEAL 等）維持原本的字母排序，因此不影響電腦強度。此修正屬於同一個未合併 PR 內的 `RankedAiVersion` 4，不需再升版。

新增測試 `TieredAiReplaysWholeGamesIdenticallyDespiteFreshInstanceIds`：各級電腦以相同種子完整打兩次，逐步比對。修正前失敗，修正後通過。
