# 天梯牌組與平衡測試

更新日期：2026-10-13。

## 試玩

開啟 [本地 5180](http://127.0.0.1:5180/) 或 [Azure 遊戲](https://wcggametienxiang0520.z11.web.core.windows.net/)，重新整理後等資源下載完成。天梯與訓練場的玩家牌組清單只列自訂牌組。新存檔會有一副 50 張的「我的入門牌組」，可直接修改；已有牌組不會被取代。選牌組使用螢幕內可捲動的視窗。

可先複製並儲存回音法陣、根鬚覺醒、聖光遠征、殘血魔潮，觀察不同流派的出牌節奏。青銅不會出現全部 30 種對手；對手數隨牌位提高，到了大師才會涵蓋全部。

在「牌組構築室」打開牌組選單，展開「競技流派參考牌組（30 套）」，按「複製並載入編輯」。5 副試玩預組也保留在同一個視窗。可改卡、另存或列印；參考牌表本身不會被修改。按「儲存牌組」後才會加入出戰清單。

更新前已開始的天梯對局會沿用當時數值，畫面有提示；下一場才套用新版。段位與戰績會保留。登入 Microsoft 並確認「雲端已同步」後可換裝置接續；匯出存檔也可另外保存。

## 完整強牌表與低段配牌

大師及 30 副參考牌組讀取 `WcgWeb/Data/ranked_master_builds.json`，每個流派使用目前候選中測得較強的固定牌表，大師不再隨機微調。青銅到鑽石仍使用產生器原有的簡化牌表與微調；平衡模擬一律比較完整強牌表。

修改大師配牌：編輯 `ranked_master_builds.json` 中對應流派的 `CardIds`，保持 50 張、同卡最多 4 張、最多兩個派系（副色張數不限；雙色卡只能放進主副色剛好相符的牌組），再執行產生器。修改低段配牌：編輯產生器的 `ARCHETYPES`／`down`／`var`；不直接手改產物 `ranked_decks.json`。自訂牌組不會因此被替換。

候選比較工具只讀專案卡池，輸出放在忽略目錄，不自動發布或替換玩家牌組：

```bash
python3 tools/DeckStrength/build_candidates.py \
  --out output/balance/strength-candidates.json \
  --opponents-out output/balance/strength-opponents.json
dotnet run --project tools/DeckStrength -c Release -- \
  --candidates output/balance/strength-candidates.json \
  --opponents output/balance/strength-opponents.json \
  --out output/balance/strength-results.json \
  --seeds 8 --seed-base 9300000 --threads 4
```

工具會列出選出候選及全部評分。這是有限候選與 AI 的比較，不能視為全域最強或真人勝率。初選後要換獨立種子複測並保留原牌表對照；未來削卡時，固定強牌表與種子，只改候選卡來觀察影響。

本輪 377 個候選、選出牌表與完整換牌清單見 [各流派完整強牌表](history/2026-10-13-各流派完整強牌表.md)。

完成強牌表後的最新改卡，見 [六張單卡平衡](history/2026-10-13-六張單卡平衡.md)：荊棘巨龜及日耀聖堂巨像降低 PP，墓園守夜人提高 PP，冥府復甦領主、母樹共鳴及滅絕怒火降費。完整強牌表固定，低段保留較弱配牌。

## 測試方法

agent-browser 實際操作用來驗證拖曳、目標選擇、回合、結算、續玩及回顧。大量平衡樣本由同一規則引擎直接模擬，兩種測試的目的不同。模擬勝率不等於真人勝率。

重新產生牌表／檢查來源一致：

```bash
python3 tools/RankedDecks/build_ranked_decks.py --check
python3 tools/CardDocs/build_cards_md.py --check
dotnet test WcgTests
```

同等強度的完整循環賽（435 組、交換先後手、27,840 場）：

```bash
dotnet run --project tools/BalanceLeague -c Release -- \
  --decks WcgWeb/Data/ranked_decks.json \
  --out output/balance/league.json \
  --seeds 32 --seed-base 8300000 --ai 5 --threads 4
```

將 `--ai 5` 換成 `--ai 3` 可比較另一種策略。`--cards` 可指定保存的完整舊卡池；`balance-before-diversity.json` 只有變動的 32 張，不可直接當成完整卡池。

檢查分段牌表、微調與五副預組難度矩陣：

```bash
dotnet run --project tools/RankedCheck -c Release -- WcgWeb 2
RANKEDCHECK_THREADS=4 dotnet run --project tools/RankedCheck -c Release -- WcgWeb 10 --matrix
```

## 隔離的瀏覽器驗證

請建立專用的 agent-browser session 與另外的測試埠，不附加玩家正在使用的瀏覽器。先將靜態建置放進忽略目錄，再啟動測試站，透過 UI 開始天梯對局。以下示例的 UI 操作策略很簡單，只作交互驗證，不作強度評估：

```bash
node SoulOath.Static/tools/build-site.mjs --azure .build-tmp/balance-test-site
# 在另一個終端啟動專用測試站：
# node SoulOath.Static/tools/serve-static.mjs .build-tmp/balance-test-site/dist 5186
agent-browser --session wcg-balance-test open http://127.0.0.1:5186/ranked
agent-browser --session wcg-balance-test snapshot -i
# 透過天梯畫面選牌組並開始對局後：
python3 tools/BrowserRanked/check_ranked.py \
  --session wcg-balance-test --port 5186 \
  --out output/balance/browser-match
agent-browser --session wcg-balance-test close
```

腳本只接受 `wcg-balance-` 開頭的 session，拒絕 5180／5179，並核對每次操作的網址。它只讀取可見 DOM，使用真正的滑鼠與按鈕操作，不直接呼叫遊戲引擎或讀取敵方手牌。
