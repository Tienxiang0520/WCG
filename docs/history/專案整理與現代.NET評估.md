# 專案整理與現代 .NET 評估

日期：2026-10-10。整理前版本：`4174671`。

## 本輪變更

1. 新增 `WCG.slnx`，將兩個主機、測試及三個 .NET 平衡工具放在同一方案。
2. 六個專案的 `net10.0`、nullable、implicit usings 統一到 `Directory.Build.props`。
3. 兩個主機重複的四份歷史卡池、三份翻譯資源移到 `build/Wcg.SharedResources.props`。所有原 `LogicalName` 與 culture metadata 保留。
4. 組牌頁從 701 行單檔拆為 395 行 `.razor` 畫面與 312 行 `.razor.cs`。原畫面與 `@code` 邏輯逐字比對相同；靜態專案同步連結 code-behind，翻譯測試同步涵蓋該檔。
5. `DeckService` 改為找到目標後只複製那一副。自訂牌組優先順序、內建牌組防覆寫、錯誤提示與版本衝突檢查保留；外部依然只取得可獨立編輯的副本。清單組合使用清楚的 collection expressions，儲存重用相同格式的 `JsonSerializerOptions`。
6. `RankedDecks` 在載入時建立六段唯讀清單，避免每次重新篩選與配置；JSON 順序與所有 RNG 呼叫保留。
7. 固定翻譯占位符模式改用 `GeneratedRegex`，動態模板保留普通 Regex。移除一個未使用的 using，並把測試輔助方法 `Legacy` 限為 internal，消除 xUnit1013 警告。

沒有更動卡片數值、效果、199 張卡的資料、136 副牌表、存檔版本、AI 強度或套件版本。沒有搬移／刪除玩家存檔、`.runtime/`、Sites checkout 或正在供應本地遊戲的檔案。使用者原有 `README.md`、`docs/設計待討論.md`、`cards.ods` 的雜湊均保留。

## 實際比對與測量

- 卡池預設 JSON 的 SHA-256 指紋相同。
- 六段各連續抽選 100 次，共 600 次；同種子、避開前一流派與隨機微調的完整牌表指紋相同。
- 七個嵌入資源名稱相同；既有歷史卡池、存檔及回放測試通過。
- 選定翻譯的結果相同；所有 UI literal、卡片、牌組、教學、策略與引擎訊息的既有翻譯測試仍通過。
- 牌組查找診斷：桌面 .NET 10 Release，無自訂牌組，找最後一副大師參考牌組；先暖機 200 次，再量 2000 次。配置量由 73,040,040 bytes 降為 3,024,040 bytes，平均由 36,520 降到 1,512 bytes／次，約減少 95.9%。單次執行時間為 82.1 → 9.1 ms，僅是這個微型診斷；不代表瀏覽器、網路、整場遊戲或普遍速度提升。

對照數據見 [相容性比對](專案整理相容性比對.json)。詳細原始輸出放在本地忽略目錄 `output/modernization/`；診斷沒有寫入玩家儲存。

- 卡牌文件與牌組產生器的 `--check` 通過。
- 靜態輸出檢查通過：199 張卡圖、1294 個檔案、150.1 MB；完整下載清單 716 項、約 129.0 MB。
- agent-browser 專用隔離 session／5186 測試站：複製根鬚覺醒、儲存後唯讀工具確認新玩家牌組 ID 與 50 張；列印預覽顯示六頁卡片；切換 English，天梯有 36 個選項（5 預組＋30 參考＋1 測試自訂）；以該牌組開始對局並結束回合，重新整理仍為第 3 回合、8 張手牌。未讀敵方手牌，沒有直接呼叫遊戲引擎。瀏覽器沒有回報頁面錯誤。
