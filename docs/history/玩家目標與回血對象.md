# 玩家目標與回血對象

日期：2026-10-10。

## 問題與改動

之前的指定目標流程只接怪物；己方頭像只有更換頭像功能。所有無指定目標的法術都可拖向敵方頭像當作施法區，因此把純回血牌拖向敵方時，實際仍自動替自己回血，操作與卡面語意不一致。

- 050 甦生之雨、066 王者賜福、070 崇高奉獻改成先選任一玩家才付款，回復被選玩家的生命。066 的抽牌仍由施法者執行。可直接拖向雙方頭像，也可先放到中央再點亮起的頭像；選擇可取消，不扣費、不丟牌。
- 其餘 18 張固定替己方回復的進場、觸發與附帶效果，僅補上「己方」文字，不改效果或數值。英譯、規則.md、cards.md 同步。199 張卡圖沿用，沒有重製卡圖。
- 雙方頭像接玩家目標 ID，合法時亮綠光，箭頭吸附、放開後移動。等待選玩家時點己方頭像會選目標；一般狀態仍可更換頭像。怪物限定法術不能把玩家當怪物選。
- 抽牌等無目標法術不再把敵方頭像當通用施法區；明確對敵方玩家造成傷害的無目標牌仍可拖向敵方。舊版對戰與開發用 Phaser 呈現同步接玩家目標。
- 回血教學改為拖向己方頭像，仍使用實際共用規則引擎。

## 相容性

新添 21 張卡的 `balance-before-player-targets.json` 歷史文字快照，先還原至此次更新前，再疊原有舊卡池。更新前卡池指紋保持 `88C0C870C9CC1E0CEA81399269174E23D1A1E7649EA41F6BB91DCAE57EABA187`；更早各版本的固定指紋測試仍保留。舊對局與回放沿用原本無指定的自我回復，下一局才使用任一玩家規則。

玩家命令沿用 TargetId，兩個固定 GUID 代表玩家頭像。天梯壓縮紀錄的 TargetSide 2／3 代表己方／敵方頭像，Target 維持 -1；怪物位置仍為 0／1，不混用。沿用行動版本 4、存檔版本 2，不清空段位、戰績或自訂牌組。新舊卡池由已保存的對局指紋選擇。

另外修正選牌組視窗的高度計算：--wcg-vh 是像素高度，不能再乘 100，避免從戰場返回後長清單再次超出螢幕。

## 驗證

測試涵蓋雙方指定、施法者抽牌、生命上限、錯誤目標與不足能量不付款、取消、重送冪等、各階 AI 自我回復，以及舊卡池指紋、新玩家目標紀錄的續玩與回放。339 項 .NET 測試及 70 項前端測試通過，六個專案建置零警告、零錯誤。21 張歷史快照以及更早各版指紋、卡表文件與天梯產生器一致性檢查通過。舊版回血卡的英文文字也保留，不會把舊對局標成新版「任一玩家」。

隔離 agent-browser 使用訓練工具，在 1440×900 的真實頁面操作：己方／敵方從 2／3 點開始，甦生之雨拖向敵方後是 2／5；王者賜福拖向己方後是 4／5 且施法者抽牌；崇高奉獻放中央後取消，仍是 4／5。切換 390×844 後再次放中央、點己方頭像，最後是 5／5，沒有打開頭像編輯。拖曳期間雙方合法頭像均亮起，瞄準箭頭存在，未觀察到頁面 JavaScript 錯誤。瀏覽器模擬尺寸不等同 Android／iOS 實機驗證。

測試首次暴露 `.dragging .player.hero{pointer-events:none}` 的舊樣式：己方雖亮綠光但放開仍無法命中。已改成只停用不合法的己方頭像，實際雙方拖曳重新驗證通過。截圖及可見 DOM 紀錄留在忽略的 `.build-tmp/player-target-browser.json` 等檔案。
