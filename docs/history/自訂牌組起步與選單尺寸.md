# 自訂牌組起步與選單尺寸

日期：2026-10-10。

## 問題與結果

原本將 5 副試玩預組、30 副流派參考牌組與自訂牌組全部放入原生下拉選單，手機展開後會超出畫面。現在天梯、訓練場與舊版對戰的玩家欄位只列自訂牌組，使用固定在螢幕內、內部可捲動的選擇視窗；Escape 可關閉，焦點留在視窗內並於關閉後回到按鈕。訓練場電腦欄位仍可選全部模板，以便測試。

新存檔首次進入時會保存一副 50 張「我的入門牌組」，使用既有卡、以低連動的怪物和簡單法術為主，沒有箭頭或結界。組牌頁先載入既有自訂牌組，牌組選單也先列自己的牌組。五副預組與 30 副流派參考仍可複製；按「儲存牌組」後才會出現在出戰清單。組牌頁載入視窗也限制在可視高度，內容內部捲動。

## 存檔保護

只在 decks 項目不存在時建立入門牌組。已有的牌組、明確的空清單（例如已刪光）、損壞或讀取失敗的資料，都不會被替換或重新補牌組。初次寫入被拒絕時顯示錯誤，不提供未保存的牌組出戰。沿用現有 GUID、Version 與樂觀寫入檢查，不更改存檔格式、天梯戰績、進行中對局或回放。

## 入門強度檢查

不改 199 張卡的效果或數值，只調整入門牌表。第一版對五副預組的模擬勝率偏高，調弱牌表後，最終使用同一 AI 等級 5、32 個種子並交換先後手，對五副試玩預組共 320 場，入門牌組 105 勝，勝率 32.81%。完整六副循環賽共 960 場。這是規則引擎的 AI 模擬，不代表真人勝率或所有對手的強度。原始檔留在忽略的 `.build-tmp/starter-strength-v3.json`。

## 驗證

- .NET 測試涵蓋初次建立、可編輯、既有資料原文保留、空／損壞資料保留、失敗寫入和共用儲存鎖避免重複建立。
- 六個專案建置零警告、零錯誤；317 項 .NET 測試、70 項前端測試通過。卡牌文件、136 副天梯資料來源與 Azure 套件檢查通過。
- 隔離的 agent-browser：390×844 選牌組視窗、844×390 的 36 選項電腦清單可內部捲動並選最後一項；320×568／844×390 組牌載入視窗不超出畫面。選牌組焦點循環、Escape 關閉與焦點還原正常；組牌浮動快捷鈕在視窗開啟時隱藏。
- 新瀏覽器恰好建立一副入門牌組，50 張牌與最終模擬牌表完全一致；複製回音法陣並保存後，天梯只顯示兩副自訂牌組，可使用副本開始對戰。既有測試存檔在更新與重整續玩後逐項相同，回合 1／手牌 7 保留。英文選牌組文字正常，頁面未觀察到 JavaScript 錯誤。
- 瀏覽器測試為 Chromium 尺寸模擬，未宣稱 Android／iOS 實機驗證。原始截圖、讀取結果、建置紀錄保存在 `.build-tmp/`；未操作玩家瀏覽器或覆蓋玩家資料。
