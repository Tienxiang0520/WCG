# 天梯牌組與平衡測試

更新日期：2026-10-10。

## 試玩

開啟 [本地 5180](http://127.0.0.1:5180/) 或 [Azure 遊戲](https://wcggametienxiang0520.z11.web.core.windows.net/)，重新整理後等資源下載完成。天梯的大廳牌組清單現在有 5 副原試玩預組、30 副競技參考牌組及你自己的牌組。

建議先試回音法陣、根鬚覺醒、聖光遠征、殘血魔潮，觀察不同流派的出牌節奏。青銅不會出現全部 30 種對手；對手數隨牌位提高，到了大師才會涵蓋全部。

在「牌組構築室」打開牌組選單，展開「競技流派參考牌組（30 套）」，按「複製並載入編輯」。可改卡、另存或列印；參考牌表本身不會被修改。未按儲存前，不會加入自訂牌組存檔。

更新前已開始的天梯對局會沿用當時數值，畫面有提示；下一場才套用新版。段位與戰績會保留。匯出存檔仍是換裝置的方式。

## 測試方法

agent-browser 實際操作用來驗證拖曳、目標選擇、回合、結算、續玩及回顧。大量平衡樣本由同一規則引擎直接模擬，兩種測試的目的不同。模擬勝率不等於真人勝率。

重新產生牌表／檢查來源一致：

```bash
python3 tools/RankedDecks/build_ranked_decks.py --check
python3 tools/CardDocs/build_cards_md.py --check
dotnet test WcgTests
```

同等強度的完整循環賽（435 組、交換先後手、27,840 場）：

```bash
dotnet run --project tools/BalanceLeague -c Release -- \
  --decks WcgWeb/Data/ranked_decks.json \
  --out output/balance/league.json \
  --seeds 32 --seed-base 900000 --ai 5 --threads 4
```

將 `--ai 5` 換成 `--ai 3` 可比較另一種策略。`--cards` 可指定保存的完整舊卡池；`balance-before-diversity.json` 只有變動的 32 張，不可直接當成完整卡池。

檢查分段牌表、微調與五副預組難度矩陣：

```bash
dotnet run --project tools/RankedCheck -c Release -- WcgWeb 2
RANKEDCHECK_THREADS=4 dotnet run --project tools/RankedCheck -c Release -- WcgWeb 10 --matrix
```

## 隔離的瀏覽器驗證

請建立專用的 agent-browser session 與另外的測試埠，不附加玩家正在使用的瀏覽器。先將静態建置放進忽略目錄，再啟動測試站，透過 UI 開始天梯對局。以下示例的 UI 操作策略很簡單，只作交互驗證，不作強度評估：

```bash
node SoulOath.Static/tools/build-site.mjs --azure .build-tmp/balance-test-site
# 在另一個終端啟動專用測試站：
# node SoulOath.Static/tools/serve-static.mjs .build-tmp/balance-test-site/dist 5186
agent-browser --session wcg-balance-test open http://127.0.0.1:5186/ranked
agent-browser --session wcg-balance-test snapshot -i
# 透過天梯畫面選牌組並開始對局後：
python3 tools/BrowserRanked/check_ranked.py \
  --session wcg-balance-test --port 5186 \
  --out output/balance/browser-match
agent-browser --session wcg-balance-test close
```

腳本只接受 `wcg-balance-` 開頭的 session，拒絕 5180／5179，並核對每次操作的網址。它只讀取可見 DOM，使用真正的滑鼠與按鈕操作，不直接呼叫遊戲引擎或讀取敵方手牌。

本輪結果、32 張數值調整與尚未解決的先手優勢，見 [天梯多樣性與數值平衡](history/天梯多樣性與數值平衡.md)。
