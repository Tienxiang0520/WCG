# 登入持續與同瀏覽器裝置控制

初版 MSAL 使用 sessionStorage，關閉分頁後帳號快取消失，即使雲端進度仍在，也會要求重新登入。改為 MSAL 5.25.0 的 localStorage，保留選取帳號，尊重 Microsoft 的 Keep me signed in 及其加密快取生命週期。沒有自行保存密碼、權杖或加密金鑰；由舊暫存版更新時，首次需由使用者登入建立新快取。

裝置租約識別改為同瀏覽器持續保存，沿用仍存在的舊分頁 UUID，避免關閉重開的 60 秒內被判為另一台裝置。等待 Web Locks 判定寫入分頁後才開始雲端流程；唯讀分頁不改存檔、偏好或租約，且不能替寫入分頁釋放控制權。靜默取得權杖時若選取帳號改變，立即停止傳送請求，保留原帳號進度。

真實 MSAL 的 localStorage 登出測試發現 logoutRedirect 的 onRedirectNavigate 回呼會觸發 BroadcastChannel DataCloneError，與官方議題 #8535 相符。使用公開 clearCache API 完成原本的「僅登出本遊戲」行為，避免序列化回呼，也避免把另一個未選取快取帳號自動登入。

驗證：27 項同步、裝置與儲存測試，其中 6 項是本次新增整合案例；全部前端建置測試 91 項，遊戲回歸 388 項。實際 MSAL SDK 在隔離的本機頁面以明確測試資料完成快取關閉重開、選取帳號登出及保留另一帳號、未選 KMSI 的 Cookie 到期情境；測試資料不送 Microsoft 或玩家 API，不能當作本人重新登入的驗證。收據在忽略的 `.build-tmp/persistent-login-*`。

參考：[Microsoft 快取規則](https://learn.microsoft.com/en-us/entra/msal/javascript/browser/caching)、[官方登入套件議題 8535](https://github.com/AzureAD/microsoft-authentication-library-for-js/issues/8535)。
